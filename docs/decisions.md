# 决策记录

| 决策 | 状态 | 理由 |
| --- | --- | --- |
| 独立开发 Continuo | 已确认 | CC Switch 为实现参考；不 fork、不改造既有个人项目 |
| 后续开源 | 已确认 | 初始项目采用 MIT；名字可用性未检索 |
| 无统一服务端 | 已确认 | 用户配置自己的同步存储；首个适配为 GitHub 专用仓库 |
| 仅三种 agent | 已确认 | Claude Code、Codex、Hermes；增加其他 agent 需新决策 |
| 接口与适配层优先 | 已确认 | agent 可通过 CLI/MCP 管理；客户端共享同一服务 |
| App + 独立 Web | 已确认 | 用户要求两种入口，共用界面和核心；Web 必须实际可操作 |
| Web 本机 HTTP → MCP | 已实现 | 浏览器无需 Tauri invoke；复用已有权限与业务接口，无自建统一后端 |
| Tauri + React/TS + Rust | 已选 | 桌面能力、配置/进程处理与共享核心；不绑定 UI 为唯一入口 |
| 独立本地 SQLite | 已选 | 离线可写；不共享运行中的数据库文件 |
| 不可变事件 + 因果父版本 | 原型已实现 | 并发版本保留、去重、删除传播、显式解决冲突 |
| Git 中保存加密事件 | 原型已实现 | 存储与业务协议分开；避免整包覆盖 |
| 本地密钥文件 | 原型临时实现 | 先验证端到端数据流；正式版需要 keychain、配对、恢复、轮换 |
| Agent 先准备计划 | 原型范围 | 验证接口，不触碰用户现有运行时；执行/投递/回滚随后实现 |
| 自动同步、增量历史、设备撤销 | 尚未实现 | 完成安全模型和协议后再开放 |
| 开发者优先/通用个人终端 | 待讨论 | 当前原型不将其视为既定产品定位 |

首个验证里程碑：两个独立数据目录，经本地 bare Git 完成加密同步；覆盖离线并发、冲突解决、删除、重复同步、错误密钥与 MCP 入口权限。真实 GitHub、真实运行时会话和打包应用需另外验证。
