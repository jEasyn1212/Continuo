# 产品边界

Continuo 让个人的工作在不同 agent、身份和设备之间持续接续。身份、任务、能力、MCP、会话、跨设备同步是共同构成产品的六个领域；provider 是连接配置的一部分。

| 领域 | 负责 | 关系 |
| --- | --- | --- |
| 身份 | 角色、偏好、明确规则与知识引用 | 引用账号和能力，不自行授予权限 |
| 任务 | 目标、状态、决策、产物与下一步 | 关联身份、会话和工作环境 |
| 能力 | Skills、规则、版本、依赖与适用条件 | 按任务和身份启用，由适配器检查支持度 |
| MCP | 工具连接、认证引用与可用性 | 区分已登记、可连接、获授权 |
| 会话 | 原生标识、agent、任务、身份、设备和环境 | 同 agent 原生恢复与跨 agent 材料接续分别处理 |
| 同步 | 可携带对象、范围、版本与冲突 | 同步所有适用领域，由设备生成本机配置 |

设备是同步与执行的基础对象。当前 `device` 实体是用户登记的设备描述，与每个本地数据库生成的 `device_id` 分开；前者不代表认证或信任。账号、权限、工作空间和环境的完整模型仍需逐步实现。

身份回答“以什么角色工作”，账号回答“向哪个服务认证”，权限回答“允许访问什么与执行什么”。身份提示词不能提供安全隔离。支持范围与实际生效状态必须由适配器明确报告。

CLI 和 MCP 是一等入口。所有工作空间操作应有机器可调用的接口；用户可以授权 agent 代为管理。授权由入口配置和应用服务共同执行，不依赖工具描述文本。

当前六类记录共用事件存储，尚未完成所有领域的业务流程。首版先验证数据与接口契约，后续加入类型化关系、配置投递、原生会话发现、设备配对和凭据引用解析。

已确定：独立开发、未来开源、仅三种 agent、首版没有自建统一服务端、用户自选同步存储、接口与适配层优先。

仍待产品讨论：开发者优先还是更通用的个人终端；原生配置的应用与回滚体验；技能正文与产物文件的同步范围。当前 CLI 与工作记录原型不构成对这些问题的最终决定。
